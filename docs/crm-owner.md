# Кабинет владельца Beauty Room

CRM находится по адресу `/crm`, форма входа — `/crm/login`. Интерфейс на русском,
а тексты процедур редактируются отдельно на русском, иврите и английском.

## Что уже сделано

- Вход по email и паролю, выход из кабинета.
- Доступ к страницам и сохранениям только у пользователя с правами владельца.
- Список процедур, поиск, создание, редактирование, архив и восстановление.
- Цена, длительность, пометки «от» и ссылка на фотографию.
- Порядок опубликованных процедур: перетаскивание карточек и стрелки вверх/вниз.
- Название, описание, задачи, этапы, типы кожи, противопоказания и примечания
  для каждого из трёх языков. Для иврита поля показываются справа налево.
- Черновики и публикация. В публичный сайт попадают только опубликованные,
  не архивированные процедуры. Сохранение обновляет данные сайта.
- Защита от перезаписи свежих изменений старой вкладкой.

Существующие 13 процедур перенесены из файлов в Neon без изменения их текстов,
цен и адресов. Переводы и сведения об источниках сохранены. Локальные копии процедур и одноразовый скрипт импорта удалены после переноса.
Новые процедуры создаются в CRM. Для новой пустой базы каталог нужно наполнить
через CRM или восстановить из резервной копии Neon.

Этот этап относится к процедурам. Управление клиентами, загрузку файлов,
редактор остальных разделов сайта и восстановление пароля по email можно
добавить следующими этапами. Сейчас фотографию задаём ссылкой на готовый файл.

## Первый вход

Учётную запись владельца создаёт разработчик в терминале. На сайте нет публичной
регистрации: посетитель не сможет зарегистрироваться и получить права владельца.

1. В терминале, открытом в папке `beauty-room`, выполни:

   ```sh
   npm run owner:create -- твой-email@example.com
   ```

   Замени пример своим email. Команда дважды попросит пароль длиной 12–128 символов.
   Ввод скрыт: символы в терминале не появляются, это нормально. Пароль не передавай
   в чат и не добавляй в команду. В базе хранится защищённое представление пароля,
   а не исходный текст.

2. Если локальный сервер ещё не запущен, выполни `npm run dev`.
3. Открой http://localhost:3000/crm/login и введи выбранные email и пароль.

Для локального входа подготовлены `BETTER_AUTH_SECRET` и `BETTER_AUTH_URL`
в `.env.local`. Секрет — случайная строка, которой приложение подтверждает,
что данные входа созданы им самим. Не публикуй её в Git.

Если переносишь изменения в другой проект или окружение, сначала установи
зависимости (`npm ci`), создай переменные окружения и выполни:

```sh
npm run db:deploy
npm run db:generate
```

Миграция добавляет таблицы пользователей, входов и защиты от частых попыток входа.
Таблица `Client` хранит клиентов студии, а `User` — тех, кто может входить в приложение.
Это разные сущности: добавление клиента само по себе не даёт ему вход в CRM.

Новая процедура создаётся кнопкой во вкладке «Черновики».

Вкладки списка: «На сайте» — опубликованные процедуры, «Черновики» — подготовка
к публикации, «Архив» — неактуальные услуги. Поиск работает внутри выбранной вкладки.

## Как редактировать

1. Нажми на карточку процедуры. Архивные карточки открывают просмотр; для редактирования сначала восстанови процедуру.
2. Измени общие параметры. Они одинаковы для всех языков.
3. Переключай вкладки «Русский», «Иврит», «English» и редактируй тексты.
   Переключение языка сохраняет ввод внутри формы; в базу он попадёт после сохранения.
4. Нажми «Сохранить черновик», чтобы продолжить позже, или «Опубликовать», чтобы показать процедуру на сайте. У опубликованной процедуры доступны сохранение изменений и перенос в архив.

Черновик может быть незавершённым. Для публикации нужны название и описание
на всех трёх языках; добавленные задачи и этапы также должны быть заполнены.
Сайт показывает новые данные при следующей загрузке или переходе.
Уже открытая у посетителя вкладка сама по себе не меняется.

Архивирование убирает процедуру с сайта, сохраняя её содержимое и историю посещений.
После восстановления процедура появляется во вкладке «Черновики» — её можно проверить и
опубликовать снова. Кнопки безвозвратного удаления нет.

## Порядок процедур

Во вкладке «На сайте» цифры слева соответствуют положению в меню процедур сайта.
Сначала нажми «Редактировать порядок процедур в списке»: появятся стрелки и значки
перетаскивания. Используй стрелки вверх/вниз или перетащи карточку за значок ⋮⋮
(работает мышью и касанием). У значка также есть управление клавишами ↑/↓.
Карточки плавно перемещаются, а цифры сразу показывают новый порядок.
Нажми «Сохранить порядок», чтобы применить изменения на всех языках сайта.
До этого момента порядок на сайте остаётся прежним. «Отмена» возвращает последний
сохранённый порядок. При ошибке сохранения изменения остаются в редакторе для
повторной попытки. При поиске сначала очисти запрос.
Если список изменён в другой вкладке, обнови страницу перед повторным перемещением.
Новая опубликованная процедура добавляется в конец списка. В черновиках и архиве
нет позиции на сайте: она появится после публикации. Из редактора порядок менять нельзя.

## Если забыт пароль

Разработчик с доступом к базе может задать новый пароль:

```sh
npm run owner:create -- твой-email@example.com --reset-password
```

Команда запросит новый пароль скрытым вводом и завершит старые сеансы входа.
Восстановление через почту пока не подключено.

## Публикация на Vercel

В окружении production понадобятся:

- `DATABASE_URL` — строка подключения к базе с pooling.
- `DIRECT_URL` — прямое подключение для миграций.
- `BETTER_AUTH_SECRET` — случайный секрет длиной минимум 32 символа.
- `BETTER_AUTH_URL=https://beautyroomky.com` — точный адрес, на котором будет вход.

Локальный `.env.local` не переносится в Vercel. Открой проект в Vercel →
Settings → Environment Variables и добавь переменные для Production.
Для `BETTER_AUTH_SECRET` можно создать отдельный случайный секрет командой
`openssl rand -hex 32` и скопировать результат в Vercel. Это не пароль владельца.
После сохранения переменных запусти новый деплой: старый их не получит.
Проверка входа выполняется при запросе страницы CRM, а не при сборке сайта;
без настроенных переменных вход на опубликованном сайте работать не будет.

Если сайт используется с `www`, адрес входа и `BETTER_AUTH_URL` должны совпадать.
Для preview нужны свои адрес и переменные; не используй автоматически production URL.
Сам сайт в этом запросе не публиковался. На реальном HTTPS-домене библиотека
устанавливает защищённые cookies; локальный HTTP нужен только для разработки.

## Что означает защита

Сессия — запись о выполненном входе, действующая ограниченное время.
Cookie — небольшая запись в браузере, которую он прикладывает к запросам.
Сервер проверяет её через Better Auth и затем проверяет права владельца.
Наличие открытой страницы или кнопки не даёт права на сохранение.

Проверка `requireOwner()` выполняется перед чтением закрытых данных и каждой
операцией создания, сохранения, архивирования и восстановления. Пароли обрабатывает
Better Auth; регистрация отключена, право владельца нельзя передать в публичной форме.
Попытки входа ограничены и учитываются в базе, а не только в памяти одного сервера.

## Проверки

При запущенном локальном сервере:

```sh
npm run test:crm
```

Тест создаёт собственные вымышленные учётные записи и процедуру, проверяет вход,
доступ, сохранение, публикацию, конфликт версий и выход, затем удаляет свои записи.
Настоящие процедуры и владельцев не изменяет. Для запуска нужен доступ к базе.
Проверка защиты порядка без подключения к базе: `npm run test:crm-order`.
После проверки можно выполнить `npm run lint` и `npm run build`.

## Где находится код

- `src/server/auth/` — настройки входа и проверка владельца.
- `src/app/api/auth/[...all]/route.ts` — запросы входа и выхода.
- `src/app/crm/` — страницы и формы кабинета.
- `src/app/crm/actions.ts` — серверные операции сохранения.
- `src/shared/model/treatment-editor.ts` — проверка введённых данных.
- `src/server/treatments/public.ts` — опубликованные процедуры для сайта.
- `scripts/database/create-owner.ts` — создание владельца и смена пароля.

Документация Better Auth: https://better-auth.com/docs/integrations/next
