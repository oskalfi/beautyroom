# Локализация

next-intl подключён для Next.js App Router.

- Английский: `/en`, `/en/contacts`, `/en/treatments/1`.
- Русский: `/ru`, `/ru/contacts`, `/ru/treatments/1`.
- Иврит (по умолчанию): `/`, `/contacts`, `/treatments/1`, `dir="rtl"`. Адреса с `/he` перенаправляются на вариант без префикса.
- `localeDetection: false`: язык URL имеет приоритет, непомеченные адреса всегда на иврите.

Настройки: `src/i18n/routing.ts`. Словари: `messages/en.json`, `he.json`, `ru.json`.
Переведены главная, Header/Footer, каталог, все 13 подробных страниц процедур,
перехваченные модальные окна, виджет доступности, подписи фото, видео и текст записи
в WhatsApp. Метаданные главной, каталога и процедур соответствуют языку URL.
Страницы контактов, косметики, заявления о доступности и их метаданные также переведены.

Русский текст процедур — `src/shared/mocks/treatments.ts`. Полные переводы —
`src/shared/mocks/treatments.en.json` и `treatments.he.json`, по стабильному ID.
Цены, длительность, фотографии и служебные evidence не дублируются в переводах.
API загружает только нужный перевод. В клиентский провайдер передаются короткие
карточки выбранного языка (TreatmentSummaries); полные описания остаются на сервере.
Клиентские компоненты используют `useLocalizedTreatments`.

Иврит наследует RTL от html. Отступы подробной страницы используют логические
CSS-свойства. Карусель, ползунок сравнения и бегущая строка сохраняют геометрические
координаты анимации; текст подсказок и фактов имеет направление выбранного языка.
Для иврита используется системный Arial: латинские Montserrat/Rosarium не нужны
для еврейских букв, поэтому их preload на главной отключён для he.

После изменения русского оригинала обновляйте оба перевода. Проверка:
`node scripts/check-translations.mjs` — ID, поля, количество пунктов, пары
заголовок/описание, ключи интерфейса, плейсхолдеры и отсутствие кириллицы в en/he.
Она проверяет полноту, но не заменяет смысловую вычитку.
Терминологические решения и источники: [translation-review.md](translation-review.md).

В клиентском компоненте:

```tsx
const t = useTranslations('Navigation');
return <span>{t('booking')}</span>;
```

В асинхронном серверном компоненте используйте `getTranslations` из `next-intl/server`.
Ключи проверяются TypeScript по английскому словарю (`src/i18n/types.d.ts`).
Добавляйте одинаковые ключи во все три словаря.

Для внутренних переходов импортируйте `Link`, `useRouter`, `usePathname` из `@/i18n/navigation`.
Для обычного `<a>` используйте `getPathname({locale, href})`; это нужно для ссылок,
которые намеренно открывают полную страницу вместо перехваченного модального окна.
Внешние адреса, `tel:`, `mailto:`, WhatsApp и пути к файлам в public локализовать не нужно.

Страницы находятся в `src/app/[locale]`. Серверные страницы вызывают `initPageLocale(params)`
перед рендерингом, чтобы использовать выбранный язык при статической генерации.
Переключатель языка выполняет полный переход, сохраняя pathname, query и hash,
чтобы не оставлять модальное окно предыдущего языка в parallel slot.
